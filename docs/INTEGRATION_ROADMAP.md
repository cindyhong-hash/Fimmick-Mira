## 0. 現況快照（整合前）— 已對照真實運行畫面（2026-06-17 截圖核實）

- **無認證系統**：無 `User` model、無登入、無角色；所有 API route 無身份驗證。
- code 入面品牌叫 `Client`（UI 有時叫「客戶」有時叫「品牌」，未統一）。
- 視覺語言：白底、深色粗體標題、**黑色 pill 主鈕**（建立客戶資料夾 / 新增活動 / 上傳參考圖）、
  **紫色 = AI 生成動作 / 啟用狀態**（素材生成、用此 Prompt 生成新圖、產品圖 toggle、選中引擎/尺寸/數量）。

### 路由與真實畫面內容
- **品牌（同事負責）**
  - `/clients`：左欄客戶資料夾（FolderOpen + 名 + 活動數），空狀態「還沒有客戶」。
  - `/clients/new`：客戶名稱、主/輔色（色票+hex）、品牌調性（tag+加入）、禁忌事項（tag+加入）、過往貼文圖（最多 5）。
  - `/clients/[id]`：標題＝品牌名；右上「品牌設定」（齒輪 outline 鈕）+「新增活動」（黑鈕）；下面係活動列表。
  - `/clients/[id]/activities/new`：活動主題 *、訴求重點 *、產品主圖 *、參考圖（最多 3）、「建立活動並生成圖片」。
  - 之後：`/[activityId]`（3 版型挑選）→ `/editor`（微調畫布）、`/edit`（改設定重生）。
- **素材庫（Verna 負責）** `/library`：**獨立頁、自己一套側欄**（‹返回客戶 + 客戶資料夾 filter：全部/各品牌），標題會顯示「素材庫 — <品牌>」。比想像中成熟好多：
  - **風格組件 tab**：圖庫（226 張）+ 類型子分頁（全部/構圖/配色/語氣/背景）；主鈕「素材生成」（紫）+「上傳參考圖」（黑）；第二層 filter pills（參考圖/背景/人像/插畫/產品成圖）；
    每張卡：**分類 badge**（產品成圖/人像/參考圖）+ **AI 引擎 badge**（FLUX.2 pro / Seedream / Nano Banana）+ 尺寸。
  - **生成圖片 tab**：「Prompt 積木組合台」
    - 套用行業範本一鍵填（護膚品/女性用品/生活電子/衣服時尚/食品飲料/家居生活）
    - 主體物件二選一：產品圖（合成用原圖）/ 文字主體（AI 生成）
    - 產品圖最多 3 件，AI 自動去背、打光、擺入所選背景，多件合成同一場景
    - 風格積木：構圖 / 配色 / 背景 / 語氣（點卡片選取，可增減）
    - 輸出尺寸：正方形 1200×1200 / 橫向 1800×1200
    - **合成方式（引擎）**：FLUX.2 edit·主力（中文字最清）/ nano-banana（場景最自然，字會糊）/ Seedream 4.5（多圖文字佳）
    - 生成數量 1–5 + 「用此 Prompt 生成新圖」（紫）
    - 下方「圖片紀錄」：成圖卡（AI生成 badge + 引擎 + 尺寸 + 說明 + 色盤）
- Prisma model：`Client`、`Activity`、`GeneratedLayout`、`StyleComponent`、`LibraryImage`

### 痛點（整合要解決）
  1. **兩套側欄、兩個世界**：client/活動頁一套側欄，`/library` 另一套（入去主側欄消失），生成嘢同品牌情境斷開。
  2. **生成入口散三處**：活動（文案+廣告圖）喺 client 頁；生成圖片 composer + 素材生成喺 library 兩個 tab。新客唔知由邊入手。
  3. **無權限** → 做唔到「客戶只睇自己」。
  4. 命名未統一（客戶 / 品牌混用）。

> ⚠️ 重要：整合方向係**保留上述所有現有功能原封不動**（引擎揀選、行業範本、分類、合成方式等），
> 只係把入口同導覽收攏 + 加權限，唔好重寫 composer。

## 1. 目標體驗（整合後）

> 🔄 2026-06-17 修訂（依用戶 feedback 順過 flow）：連動帳號提前到登入之後第一步；
> 工作區只剩 **3 個 tab**；取消「生成圖片」tab（功能併入「廣告活動圖」頁）。

### 1.1 整體流程（順序）

```
① 登入 (NextAuth)
② 連動帳號  ← 登入後第一步：Meta / Google / IG OAuth，拉返廣告圖 / 活動圖 / IG 貼文相做素材
            （未過審 → 手動上載 fallback）
③ 品牌設定  沿用 BrandSettingsForm（名稱、主/輔色、調性、禁忌、過往貼文圖）
④ 品牌工作區（統一側欄；INTERNAL 睇所有品牌 / CLIENT 只睇自己）
```

### 1.2 工作區只有 3 個 tab

| Tab | 內容 | 對應現有 |
|-----|------|---------|
| **廣告活動圖** | 頁內 3 個生成動作鈕：`+新增活動`（黑）、`+新增圖片`（紫）、`+新增素材`（紫）+ 成果 gallery | 現有 client 活動頁 + 把 composer / 素材生成 搬入做頁內動作 |
| **風格組件** | 圖庫（分類 + 引擎 badge）、素材生成、上傳/拉返嘅參考圖 | 現有 library 風格組件 tab |
| **連動帳號** | 管理已連帳號、重新拉素材 | 新增（首次連動喺步驟 ②） |

- **品牌設定** 維持做標題列齒輪鈕（唔做 tab）。
- ❌ **取消「生成圖片」tab**：所有 AI 設計動作已經喺「廣告活動圖」頁，毋須獨立 tab。
- ⚠️ **去重複**：tab 列 = 分區導覽；生成動作 = 頁內按鈕。唔好兩處都放生成入口。

### 1.3 生成動作（喺「廣告活動圖」頁內，非 tab）

全部自動套用該品牌嘅色 / 調性 / 風格組件，並接受上傳參考圖：

| 動作 | 開乜 | 對應現有功能 |
|------|------|------------|
| 新增活動 | 活動表單 → 3 版型 → 微調畫布 | 現有「活動」流程 |

| 新增素材 | 產品合成 / 去背，成品存返風格組件 | 現有素材生成 |

### 1.4 命名統一建議

- UI 一律叫「品牌」；只有 INTERNAL 嘅跨品牌總覽先用「客戶」。
- 令 CLIENT 角色見到嘅字眼一致（佢哋只係一個品牌）。

## 2. 權限架構（整合前提）

### 2.1 角色

| 角色 | 睇到 | 睇唔到 |
|------|------|--------|
| INTERNAL（公司） | 所有客戶文案 / 資料 / 草稿 / 跨品牌素材庫 | — |
| CLIENT（客戶） | 我哋提供嘅素材 + 自己生成嘅圖 | 內部草稿、其他客戶、未發布素材 |

### 2.2 資料模型新增

- `User`（id, email, role: INTERNAL | CLIENT, …）
- `Membership`（userId ↔ clientId，多對多；CLIENT 通常綁一個品牌）
- 既有資料可加 `visibility` / `isPublished` 欄位區分「內部草稿 vs 客戶可見」。

### 2.3 落地要點

- 用 **NextAuth**（先 email / Google 登入）。
- **每個 API route 都要 row-level scoping**：CLIENT 一律 `where clientId in (我所屬品牌)`，並過濾未發布素材。⚠️ 呢步唔做＝權限形同虛設。
- Middleware 守路由：CLIENT 入唔到 `/clients`（總覽）同跨品牌素材庫。

## 3. 帳號連動（Connections）— 分階段

技術上 **Meta / Google / IG 三個都做得到**，但都要 OAuth + 平台審核。

### 3.1 各平台

| 平台 | API | 攞到咩 | 門檻 |
|------|-----|--------|------|
| Meta（FB Ads） | Marketing API · `adcreatives` edge | 廣告圖 + 文案 | FB App、OAuth、`ads_read`；Advanced Access 要 Business Verification + App Review |
| Instagram | Instagram Graph API · `/media` | 貼文相 | IG 要商業/創作者帳號 + 連 FB 專頁；`instagram_basic` |
| Google Ads | Google Ads API · GAQL `ImageAsset` | 帳戶圖片素材 | developer token（要審批）、OAuth、通常需 manager account |

### 3.2 共通限制（要同客戶講清楚）

1. **只攞到客戶授權咗嘅帳戶** — 必須客戶行 OAuth 同意，唔可以靜雞雞抽。
2. **審核期** — Meta / Google app review 要幾星期，唔係即日得。
3. Token 要管理（refresh、過期）、有 rate limit。

### 3.3 建議分階段

- **Phase 0（過渡）**：先做「手動上載參考圖 / 貼 IG 連結」，UX 位置同正式連動一樣，將來 swap。
- **Phase 1（pilot）**：先做 **Meta 一個平台**（FB Ads + IG 一次過），行通流程。
- **Phase 2**：加 Google Ads。

來源：[Meta Ads API 指南](https://www.adstellar.ai/blog/meta-advertising-api-integration) · [adcreatives 設定](https://admanage.ai/blog/meta-ads-api) · [Google Ads 取 assets](https://developers.google.com/google-ads/api/docs/assets/fetching-assets) · [Google developer token](https://developers.google.com/google-ads/api/docs/api-policy/developer-token) · [Instagram Graph API](https://developers.facebook.com/docs/instagram-platform/overview/)

## 6. 本輪確認（2026-06-18，與用戶逐項拍板）

- **兩種紀錄各有家，唔混**：活動＝**List View**（喺「廣告活動圖」tab）；圖片／素材＝**Grid 圖庫**（喺「風格組件」tab）。儲存時複製一份副本入風格組件做可重用素材。
- **生成掣擺位**（避免重複）：`+新增活動` 喺「廣告活動圖」；`+新增圖片`、`新增素材` 喺「風格組件」（出品就喺嗰個圖庫）。
- **新增活動**：可 AI 文字 or 上傳圖，可**框選範圍改善**，含廣告文案；每次 1–3 張；按儲存先入風格組件。未來：組合式活動圖（FB 一橫圖＋三方圖，未做）。
- **新增圖片**＝生成產品圖片：產品主圖＋文字積木＋揀背景＋生成 N 張；**唔加「參考圖」**（用戶決定：產品圖最後跟文字，參考圖無用）。
- **新增素材**（素材生成）：純背景／人像／2D 插圖；同 新增圖片 **唔合併**。各子類有預設引擎：**背景 FLUX.1 schnell · 人像 FLUX.2 pro 真人寫實 · 插畫 Recraft V3 2D**。**有「參考風格圖」（選填）** —— AI 讀色調／光影／質感；引擎 Nano Banana 做「風格遷移（需有參考圖）」。⚠️ 即係參考圖喺「素材圖片」係用得着嘅（同產品成圖唔同）。

### 四種圖嘅差別（2026-06-18 對照真實設定）

| | 引擎 | 主要輸入 | 參考圖 | 文案 | 出品存去 |
|---|---|---|---|---|---|
| 產品成圖（新增圖片） | FLUX.2 edit／nano-banana／Seedream | 產品主圖 或 文字 ＋ 風格積木 | ❌ | ❌ | 風格組件「產品成圖」 |
| 素材圖片（素材生成） | 背景 FLUX.1／人像 FLUX.2 pro／插畫 Recraft V3／Nano Banana 風格遷移 | 文字描述 | ✅ 選填（色調/光影/質感） | ❌ | 風格組件「背景／人像／插畫」 |
| 參考圖 | 唔生成 | 上傳 / 連動拉 | 自己就係參考 | ❌ | 風格組件「參考圖」 |
| 廣告活動圖（新增活動） | 活動流程（生圖＋圖上文字） | 主題＋訴求＋產品主圖＋參考圖 | ✅ 最多 3 | ✅ 廣告文案 | 廣告活動圖 List ＋ 風格組件「廣告活動圖」 |
- **參考圖**：只放「新增活動」（創意排版先用得著）；可由風格組件「圖片風格」modal →「用作參考」送去 新增活動 / 新增圖片。
- **連動**：背後一次 Meta 授權，但 UI 把 **Facebook / Instagram 分開兩個來源開關**（IG 需 link FB 專頁；攞廣告圖一定行 FB/Marketing API）+ Google；第三 tab 以 onboarding 為主，**唔做「已發布／成果」view**。
- **權限**：內部保留「**全部（跨品牌）**」view + 切換任何客戶 + 新增品牌 + 睇草稿；客戶只見單一品牌（隱藏草稿／其他客戶）。進入品牌後 3 個 tab 介面一致。

### 6.1 Search & Filter 規格（新加）

跨「圖庫」同「積木」嘅快速搜尋 + 篩選。可篩欄位（全部係現有 schema 已有）：

| 對象 | 可篩 / 可搜 |
|------|------------|
| 圖片（LibraryImage） | 標題 `subject`、分類（產品成圖/人像/插畫/背景/參考圖）、AI 引擎、尺寸、日期、主色 |
| 積木（StyleComponent） | 標題 `name`、類型（構圖/配色/語氣/背景）、**內文文字**（構圖的內文/標題） |
| 全文搜尋 | 即時 match 標題 ＋ 內文 ＋ `aiPromptText` / `copyText` 關鍵字 |

> ⚠️ 要做 filter，部分項目需要喺生成 / 儲存時補齊 metadata（如標題、分類 tag）—— 列入 backlog。

### 6.2 活動圖儲存入風格組件（2026-06-18 確認）

- **日期 filter 拎走** → 改輕量「排序（最新／最舊）」；生成頻率低，唔需要 date range。
- **新增圖庫分類「廣告活動圖」**（與「產品成圖」並列）：由活動 save 過嚟嘅成品入呢類，卡片標「有文案」。
- 儲存時 **AI 自動記低積木內容**；asset 詳情（modal）保留現有架構，但「廣告活動圖」類**多兩格**：
  - **廣告文案**（可開關顯示／隱藏）—— 同來源活動保持一致
  - **來源活動連結**（跳返去原活動）
- 即係 modal 有兩種：產品成圖＝圖＋AI Prompt；廣告活動圖＝圖＋AI Prompt＋文案＋來源連結。

### 6.3 修正（2026-06-18，對照真實設定後）

- **參考圖**：輸入＝上傳 **或** 由連動拉；**拉返嘅會自動抽出積木**（構圖/配色/語氣/背景）。唔係單純「自己做參考」。
- **廣告活動圖**：參考圖標「有」即可（約一張，唔使標數量）；文案係**生成**嘅；完整廣告 ＝ **圖 ＋ 廣告文案 ＋ 一張有文字嘅 AI 生成圖**。
- **廣告 asset modal**：
  - ❌ 拎走「展示／隱藏文案」toggle（無用）→ 改 **「複製文案」按鈕**（一撳 copy）。
  - 文案永遠顯示（同來源活動一致）。
  - ✅ 加返「**用作參考（匯入去生成）**」：送去 新增活動 / 新增圖片 —— 因為佢分類本身就係廣告活動圖，攞嚟做參考好合理。
- **四種對照表**以 6.2／本節為準（產品成圖無參考圖；素材圖片有參考風格圖；參考圖拉返有積木；廣告活動圖有文案）。

### 6.4 積木點嚟（四種對照加多一維）

| | 積木 |
|---|---|
| 產品成圖 | ⬇ **攞積木做輸入**（揀構圖/配色/背景/語氣餵生成）—— 唯一一種輸入用積木 |
| 素材圖片 | ⬆ 成品自動抽出（無積木輸入） |
| 參考圖 | ⬆ 上傳/拉返自動抽出（構圖/配色/語氣/背景）；「自己就係參考」 |
| 廣告活動圖 | ⬆ 成品自動記低（構圖/配色/語氣）＋文案 |

> 分野：只有「產品成圖」係**輸入**用積木，其餘三種係**事後抽出**積木存返庫。

### 6.5 四種 asset model（2026-06-18 對照真實 modal 核實）

撳入 asset 嘅「圖片風格」modal 共通：縮圖＋標題＋**移到…（公用（全部客戶）／個別客戶）**＋下載／調整／刪除＋抽出積木卡（構圖/配色/語氣…，**逐個有「帶入生成」**＝真實版「用作參考」）。

| 欄位 | 產品成圖 | 素材圖 | 網頁參考圖 | 廣告活動圖 |
|---|---|---|---|---|
| AI Prompt | ✓ 合併 | ✓ 背景描述 | ✗（非生成） | ✓ 積木 |
| 重新生成（載入原參數到生成台） | ✓ | ✓ | ✗ | ✓ |
| 來源 | 來源產品圖（1+） | 參考風格圖（選填） | 上傳／連動拉 | 來源活動 ↗ |
| 抽出積木＋帶入生成 | ✓ | ✓ | ✓ | ✓ |
| 廣告文案（＋複製） | ✗ | ✗ | ✗ | ✓ |
| 移到（公用／客戶） | ✓ | ✓ | ✓ | ✓ |

重點：
- **「移到…公用（全部客戶）／個別客戶」** = asset 已有**共享範圍**機制 → 同權限／內部「全部」view 直接相關，做權限時要尊重呢個欄位。
- **「帶入生成」**已經係現有功能（逐個積木）→ 之前我叫「用作參考」嘅嘢，真實名係「帶入生成」，唔使另做。
- 參考圖無 AI Prompt／重新生成；廣告活動圖獨有 廣告文案＋來源活動。
